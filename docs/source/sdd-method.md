# SDD method note

The internal SDD participant guide defines the evidence shape used for this repository: a business journey with failures, a question log, business decisions kept apart from technical decisions, a structured specification, and Given / When / Then acceptance criteria.

The guide's worked example is a different feature. Its rules are not requirements of the Internal Job Portal.

This baseline stops before API contracts, a technical plan, tasks, and code. Those are later stages. They wait until the open questions in `.ai-context/BRD.md` have an owner and an answer.
